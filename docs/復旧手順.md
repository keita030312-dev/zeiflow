# 障害時 復旧手順

ZeiFlow が動作しなくなった場合、または重要データが失われた場合の復旧手順です。

---

## 障害レベル定義

| レベル | 状態 | 対応開始 |
|---|---|---|
| **L1: 軽微** | 一部画面が表示遅延・特定機能のみエラー | 翌営業日 |
| **L2: 中度** | OCR処理停止・特定顧客のみログイン不可 | 4時間以内 |
| **L3: 重大** | 全ユーザーログイン不可・データ破損疑い | 1時間以内 |

詳細SLAは [SLA.md](./SLA.md) 参照。

---

## 一次対応(まず確認すること)

### 1. ヘルスチェック
```
GET https://<本番ドメイン>/api/health
```
- 200 OK: アプリは動いている → DBや外部API側の問題かも
- 5xx エラー: アプリ自体がダウン

### 2. Vercel ステータス確認
- https://www.vercel-status.com/ で Vercel自体の障害がないか確認
- Vercel ダッシュボード > Deployments で最新デプロイがエラーになっていないか

### 3. データベース接続確認
```bash
# ローカルから本番DBに接続できるか
npx prisma db pull
```

### 4. Anthropic API 確認
- https://status.anthropic.com/ で Claude API の障害有無

### 5. メール(Resend)確認
- https://status.resend.com/

## メンテナンスモード

緊急時、ユーザーアクセスを止めて作業する場合:

```
POST https://<本番ドメイン>/api/maintenance
Body: { "enabled": true }
```

- メンテナンスモード中: ユーザーは「メンテナンス中」画面を見る
- 解除: 同エンドポイントに `{ "enabled": false }` を送信

## バックアップからの復旧

### バックアップ取得

定期バックアップ(自動)に加え、手動で取る場合:

```
GET https://<本番ドメイン>/api/backup
```

→ ダウンロードされたファイルを安全な場所(別クラウドストレージ推奨)に保管

### 復旧手順

> ⚠️ **本番DBへの書き戻しは破壊的操作です。実行前に必ず最新バックアップを別途取得してください。**

1. メンテナンスモードON
2. 現状のDBダンプを取る(失敗時の戻し用)
   ```bash
   pg_dump $DATABASE_URL > rollback-$(date +%Y%m%d-%H%M).sql
   ```
3. バックアップファイルから復旧
   ```bash
   psql $DATABASE_URL < backup.sql
   ```
4. アプリ再起動 / Vercel 再デプロイ
5. ヘルスチェック OK 確認
6. メンテナンスモードOFF
7. ユーザーに復旧通知

## 環境変数を見失った場合

Vercel ダッシュボード > Settings > Environment Variables から再取得。
ローカル `.env` も同期しておくこと。

必須:
- `DATABASE_URL`
- `ANTHROPIC_API_KEY`
- `RESEND_API_KEY`
- `NEXTAUTH_SECRET`
- `NEXTAUTH_URL`

---

## 再発防止

復旧後、必ず以下を行うこと:

1. **障害報告書作成**(発生日時/影響範囲/原因/対処/再発防止策)
2. [../bugs.md](../bugs.md) に記録
3. SLA違反があった場合 → [SLA.md](./SLA.md) のペナルティ条項を確認
4. 顧客への報告メール(障害発生から24時間以内)
