# OCR精度測定手順(納品時の必須実施)

ZeiFlow の OCR 精度を客観数値で示すための測定手順です。
**この測定結果を持って初めて、契約・営業の説得材料になります。**

---

## 必要なもの

- テストレシート画像 **20〜100枚**(多いほど信頼度高い)
- ZeiFlow 本番環境 or 開発環境
- スプレッドシート(Excel/Google Sheets)
- 集計用テンプレ → [../ocr-accuracy-log.md](../ocr-accuracy-log.md)

### サンプルレシートの集め方

実態を反映する分布で集めること:

| カテゴリ | 推奨枚数 | 例 |
|---|---|---|
| コンビニ | 5〜10 | セブン/ファミマ/ローソン |
| 飲食店 | 5〜10 | チェーン+個人店 |
| タクシー/交通 | 3〜5 | タクシー領収書/Suica利用履歴 |
| 文具/消耗品 | 3〜5 | アスクル/ヨドバシ |
| ガソリン/車両 | 2〜3 | スタンドのレシート |
| 宿泊/出張 | 2〜3 | ホテル/旅館 |
| 手書き領収書 | 3〜5 | 個人商店等(精度低めが想定される) |
| インボイス番号あり | 全体の70% | 必ず混ぜる |
| インボイス番号なし | 全体の30% | 個人事業主等 |

---

## 測定手順

### Step 1: 正解データを準備

各レシートを目視で確認し、スプレッドシートに正解値を記録:

| # | 画像名 | 正解 date | 正解 total | 正解 taxRate | 正解 invoiceNumber | 撮影品質 |
|---|---|---|---|---|---|---|
| 1 | r001.jpg | 2026-04-15 | 1080 | 0.10 | T1234567890123 | 良 |
| 2 | r002.jpg | 2026-04-16 | 320 | 0.08 | (なし) | 良 |
| 3 | r003.jpg | 2026-04-17 | 5500 | 0.10 | T9876543210987 | 普通(やや暗い) |

撮影品質の判定:
- **良**: 全体が鮮明、十分明るい、平坦
- **普通**: 軽い影/ヨレあり、判読は可能
- **悪**: ぼけ/暗い/欠け、判読困難

### Step 2: ZeiFlow にアップロード

各画像を ZeiFlow にアップロードして、OCR結果を取得。
**quality は両方測定する**:

- `fast`(既定): Sonnet 4.6 主力
- `accurate`: Opus 4.7 主力 + 検証OCR

### Step 3: OCR結果を記録

| # | OCR date | OCR total | OCR taxRate | OCR invoiceNumber | fast/accurate | 処理時間(秒) |
|---|---|---|---|---|---|---|
| 1 | 2026-04-15 | 1080 | 0.10 | T1234567890123 | fast | 4.2 |
| 1 | 2026-04-15 | 1080 | 0.10 | T1234567890123 | accurate | 8.1 |
| 2 | 2026-04-16 | 320 | 0.08 | null | fast | 3.8 |
| ... |

### Step 4: 正答率を計算

各項目で「正解と完全一致した割合」を計算:

```
date 正答率 = 完全一致した枚数 / 全枚数
total 正答率 = 完全一致した枚数 / 全枚数
taxRate 正答率 = 完全一致した枚数 / 全枚数
invoiceNumber 正答率 = 完全一致した枚数 / (インボイス番号があるレシートの枚数)
```

### Step 5: 集計表を作成

| 項目 | fast 正答率 | accurate 正答率 | 平均処理時間(fast) | 平均処理時間(accurate) |
|---|---|---|---|---|
| date | 92% (92/100) | 96% (96/100) | 4.5秒 | 8.2秒 |
| total | 95% (95/100) | 98% (98/100) | - | - |
| taxRate | 89% (89/100) | 93% (93/100) | - | - |
| invoiceNumber | 86% (60/70) | 91% (64/70) | - | - |

### Step 6: 不正解ケースの分析

不正解だったケースを5件以上ピックアップして原因を記録:

```markdown
- **r023.jpg**: total が誤認識(1080円→1060円)
  - 原因: 印字が薄く「8」が「6」に見える
  - 対処: 撮影品質ガイド「明るい場所で再撮影」を顧問先に共有

- **r047.jpg**: invoiceNumber が抜けた
  - 原因: レシート下端が欠けている
  - 対処: 撮影時に全体が入るよう案内

- **r068.jpg**: date が前年になった(2026→2025)
  - 原因: レシートに年が「26」と省略表記
  - 対処: ナレッジに事務所固有のルールを追加
```

## 合格基準(目安)

| 評価 | OCR合計正答率 |
|---|---|
| 🥇 営業しやすい | 90%以上 |
| 🥈 月額契約取れる | 85%以上 |
| 🥉 改善必要 | 80%未満 |

特に **インボイス番号 90%超** は重要(顧問先の仕入税額控除に直結する)。

---

## 結果の活用

測定結果は以下の場所で活用:

1. **営業資料**: 「OCR精度 96%」のような数値を1ページ目に
2. **README**: 公開可能なら数値を載せる
3. **既知の制限**: 不正解ケースから推奨撮影条件を更新
4. **改善計画**: 弱い項目を優先的にプロンプト改善

---

## 継続的な測定

- **月次**: 実運用で発生した不正解ケースを蓄積
- **モデル更新時**: Anthropic からモデル更新があったら再測定
- **プロンプト変更時**: 必ず変更前後で測定して効果を確認

> 不正解ケースは [../bugs.md](../bugs.md) に記録し、改善は [../tasks.md](../tasks.md) で追跡。
