## 2. 障害レベル別の対応SLA

| レベル | 例 | 一次返信 | 復旧目標 |
|---|---|---|---|
| **L1: 軽微** | 一部画面表示崩れ・特定機能のみエラー | 1営業日以内 | 5営業日以内 |
| **L2: 中度** | OCR処理停止・特定顧客のみログイン不可 | 4時間以内 | 24時間以内 |
| **L3: 重大** | 全ユーザーログイン不可・データ破損疑い | 1時間以内 | 8時間以内 |

詳細は [SLA.md](./SLA.md) 参照。

## 3. 障害報告のテンプレート

連絡時に以下の情報をご提供いただけると、対応が早くなります。

```
【障害報告】
■ 発生日時: 2026-04-29 14:30 頃
■ 影響範囲: 全ユーザー / 特定ユーザー(○○事務所のみ) / 自分のみ
■ 症状:
  (例) ログインボタンを押すと「500 Internal Server Error」が表示される
■ 再現手順:
  1. https://... を開く
  2. メアド・パスワード入力
  3. ログインボタン押下
  4. エラー画面
■ 環境: PC/スマホ、ブラウザ、OS
■ 緊急度: L1 / L2 / L3
■ スクリーンショット: 添付
```

---

## 4. エスカレーション基準

### 一次窓口で30分対応しても解決しない場合
→ 開発元代表に直接連絡(緊急電話)

### データ消失・漏洩の疑いがある場合
→ **即座に** 緊急電話 + 緊急メール

### 顧問先(クライアント企業)からのクレームに発展した場合
→ 開発元と税理士事務所で **3者間MTG** を48時間以内に設定

---

## 5. 障害発生時の手順(事務所側)

1. **症状を記録**(スクショ・エラーメッセージ・操作履歴)
2. **影響範囲を確認**(自分だけ? スタッフ全員?)
3. **上のテンプレで連絡**(該当レベルの窓口へ)
4. **顧問先への影響がある場合** → 別途顧問先に連絡(連絡文面テンプレは下記)

### 顧問先への連絡文面テンプレ
```
○○様

いつもお世話になっております。
現在、当事務所が利用しているレシート処理システム「ZeiFlow」に
障害が発生しており、ご送付いただいたレシートの処理が遅れる可能性があります。

【影響】
- レシート画像の送信は引き続き可能です
- 仕訳作成が一時停止しております

【復旧見込み】
本日 ○時頃までに復旧予定です。

ご迷惑をおかけし大変申し訳ございません。
```

---

## 6. 復旧後の対応

開発元から以下が提供されます:

- **障害報告書**(発生日時/原因/対処/再発防止策)を72時間以内
- SLA違反があった場合、[SLA.md](./SLA.md) のペナルティ条項に基づく月額減額

---

## 7. メンテナンス予定の事前通知

定期メンテナンスは原則:
- 平日 22:00以降 または 土日
- **3営業日前まで** に メール通知
- 緊急セキュリティパッチは事前通知なしの場合あり(48時間以内に事後報告)
