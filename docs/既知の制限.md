# 既知の制限・OCR失敗ケース・推奨撮影条件

ZeiFlowのOCRはAnthropic Claude APIを利用しています。高精度ですが、以下の条件下では精度が落ちる/失敗することがあります。事前に共有することで運用トラブルを防げます。

---

## 推奨撮影条件(OCR成功率を上げる)

### ✅ 良い撮影
- レシート全体が画面に収まっている
- 平らな面で撮影(ヨレ・折れなし)
- 明るい場所で撮影(影が落ちていない)
- 文字がくっきり読める解像度
- レシートの上下方向が正しい

### ❌ 避けるべき撮影
- レシートの一部が画面外に切れている
- 暗い場所・逆光での撮影
- ヨレ・折れ・濡れによる印字欠け
- 極端な斜め撮影
- 複数のレシートを1枚に並べて撮影

---

## OCRが苦手なケース

| ケース | 影響 | 対処 |
|---|---|---|
| **印字が薄い古いレシート** | 日付/金額が読めず空欄になる | 手入力で補完 |
| **手書きの領収書** | 数字の誤認識が起きやすい | 結果を必ず目視確認 |
| **インボイス番号が小さく印字** | 番号の一部が抜ける | 拡大して再撮影 |
| **長尺レシート(店内飲食の長い領収書)** | 文字が圧縮されて誤認識 | 上下を分けて2枚で撮影 |
| **コピー(白黒コピー)のレシート** | 元レシートより精度低下 | 可能なら原本撮影 |
| **海外レシート(英語以外)** | 想定外、対応未確認 | 手入力推奨 |
| **税率が明示されていないレシート** | 税率欄は空欄(無理に判定しない仕様) | 必要に応じて手動入力 |

## システム上の制限

### アップロード
- 1ファイル最大: **10MB**
- 対応形式: **JPG / PNG / WEBP / GIF**
- 1度にアップロード可能枚数: 制限あり(本番E2Eで実測予定)

### OCR処理
- 1枚あたりの処理時間: 通常 **5〜15秒**(混雑時はそれ以上)
- 同時並行処理数: Anthropic APIのレート制限に依存
- 大量(1日数百枚以上)の連続処理は事前に相談

### データ保持
- 仕訳データ: 削除されるまで永続保存
- アップロード画像: 仕訳と紐づいて保存
- 監査ログ: 全操作を保存(削除不可)

## 仕訳の判定について(重要・法務)

ZeiFlowは **仕訳候補の自動生成ツール** です。最終的な勘定科目の判定・税務判断は **税理士の責任で行う** 前提で設計されています。

- 自動生成された仕訳は **必ず税理士が確認・確定する** 運用を推奨
- 監査ログには「誰がいつ確定したか」が記録されます
- 税理士法に基づく税務代理・税務相談は本サービスの範囲外です
